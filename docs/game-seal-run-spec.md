# Seal Run — спека механик v1 (SR-01)

**Нормативная спецификация** для реализации SR-02 (`core/course.js`), SR-03 (`core/sim.js` +
`core/balance.js`) и SR-04 (fairness-харнесс). Дизайн-обоснования («почему») — в
[game-seal-run.md](game-seal-run.md); здесь — «что именно и с какими числами». При расхождении
формул/констант первичен этот файл. **Все константы — предварительные** (первый проход §1.4
дизайн-дока сохранён): фиксируются только после прогона харнесса SR-04; менять — через
`tools/compare-variants.mjs`, не «на глаз».

Сводная таблица констант — в конце (§14); реализована в `core/balance.js` (SR-03) — при
расхождении чисел спека первична, рассинхрон = баг. Тюнинги живут в **мутируемом объекте `BAL`**
(SR-04): его подменяет ТОЛЬКО `tools/compare-variants.mjs` для seeded A/B; рантайм игры и sim
никогда не мутируют.

## 1. Мир, единицы, вьюпорт

### 1.1 Логические единицы и координаты
Всё в **логических единицах (lu)**, как у Seal Hunter (`VIEW_CFG.logicalShort = 540`):

* **Высота мира `WORLD_H = 540 lu`** — фиксирована для всех устройств. Ось Y: `0` = поверхность
  воды, `540` = дно. Игровая зона тюленя: `y ∈ [SEAL_R, WORLD_H − SEAL_R]`.
* **Дистанция тюленя** `d` (lu) растёт со скоростью `effSpeed`. Независимая координата
  течения/камеры — `worldD`; `d = worldD − lag`. Экранный X тюленя =
  `SEAL_X − lag`, где `SEAL_X = 240`, а отставание ограничено 110 lu (§4.2).
* **Дисплейные метры:** `distance_m = floor(d / LU_PER_M)`, `LU_PER_M = 40`. Полная трасса
  `COURSE_LENGTH_LU = 36000` → **900 м**.

### 1.2 Вьюпорт — равный горизонт (решение SR-01)
**Видимое поле фиксировано: `FIELD_W × WORLD_H = 960 × 540 lu` (16:9), contain-fit** в любой экран;
остаток вьюпорта — декорированный бордюр (небо над поверхностью / дно снизу / туман-глубина по
бокам — та же дисциплина «край бухты», что у бордюров Seal Hunter).

Почему строже, чем 2:1-кламп Seal Hunter: в раннере видимая дистанция вперёд — это буквально
**время реакции**. Горизонт игрока = `FIELD_W − SEAL_X = 720 lu` ≈ 1.7 с на плато скорости — у всех
одинаково до дебаффа; отставание прибавляет одинаковые на всех устройствах 0–110 lu. Незакланченный вьюпорт дал бы 4:3-экрану ~1.1 с, а 2:1 — ~2.0 с (+75% времени реакции) —
неприемлемый разброс для общего лидерборда. **Доска единая** (решение 2026-07-03): равный горизонт
устраняет девайс-зависимость мира, поэтому деления `desktop`/`mobile` нет — и Seal Hunter приведён
к единой доске для консистентности. Ревизия решения — только с данными SR-04/SR-05.

### 1.3 Детерминизм (фундамент анти-чита SR-10 и golden-тестов SR-14)
* **Фиксированный шаг симуляции `SIM_DT = 1/120 c`** (accumulator в рендер-слое; рендер
  интерполирует между sim-состояниями). Никакой физики от кадрового `dt` — в отличие от Seal Hunter
  (там переменный `dt` допустим: мир не общий; здесь трасса общая, коллизии обязаны сходиться).
* **RNG:** только проектный `mulberry32` (побитовая копия `core/alias.js`), только в
  `generateCourse` (§9) и только паттерном `Math.floor(rnd() * n)` (целочисленные выборы, как
  `makeParts`). В рантайме симуляции RNG **нет вообще**: движение хищников — чистые функции от
  координаты течения worldD (§6.2). `Math.random` — только в декоре (частицы, фоновая живность), который не
  участвует в коллизиях/балансе (аналог `WIGGLE` у prey Seal Hunter).
* **Никакой накапливаемой float-арифметики в данных трассы:** `atLu`, `lenLu`, позиции банд —
  целые; суммы дистанций чанков — целочисленные.

## 2. Управление — свободный Y, eased target-Y follow

Игрок управляет **только целевым Y** (`targetY`); X авто-скроллится. `targetY` кламп
`[SEAL_R, WORLD_H − SEAL_R]`.

### 2.1 Источники ввода (последний выигрывает)
| Ввод | Поведение |
| --- | --- |
| Касание/перетаскивание (mobile) | Пока палец на экране: `targetY = touchY` (в lu) каждый sim-тик. Отпустил — `targetY` замирает на последнем значении (тюлень доплывает и держит глубину). |
| Указатель мыши (desktop) | `pointermove` над canvas ставит `targetY = pointerY`. |
| `↑`/`↓`, `W`/`S` | Пока зажато: `targetY` движется со скоростью `KEY_TARGET_SPEED = 480 lu/с` в направлении клавиши. Перебивает последний pointer-target. |

Жест плавания — не «target» в смысле WCAG (target ≥24 px применяется к HUD/кнопкам — SR-07).
Во время хит-стана (§6.4) ввод игнорируется, но `targetY` продолжает обновляться (после стана
тюлень плывёт к актуальной цели).

### 2.2 Физика следования (1D ARRIVE — та же философия, что stepSeal Seal Hunter)
Каждый sim-тик (`dt = SIM_DT`):

```
vyDes = clamp((targetY − y) / TAU_Y, −VY_MAX, +VY_MAX)   // желаемая скорость
vy   += clamp(vyDes − vy, −AY_MAX·dt, +AY_MAX·dt)        // ограниченный разгон к ней
y    += vy·dt;  y = clamp(y, SEAL_R, WORLD_H − SEAL_R)   // интеграция + кламп
```

При активном дебаффе мусора пределы VY_MAX и AY_MAX умножаются на 0.65; цель и TAU_Y не меняются.

Константы: `VY_MAX = 420 lu/с`, `AY_MAX = 2600 lu/с²` (разгон до максимума ~0.16 с — «снапи», как
у Seal Hunter), `TAU_Y = 0.12 c` (мягкое торможение у цели: в зоне `|targetY − y| < VY_MAX·TAU_Y ≈
50 lu` скорость линейно спадает — eased-follow без осцилляций).

**Производные величины (для авторинга чанков и lint-правил §9.4):** сквозной проход одной полосы
(108 lu, без стабилизации на цели) ≈ **0.34 с** (разгон 0.16 с + 74 lu на `VY_MAX`); весь столб
воды (432 lu) ≈ **1.1 с**. Для lint-правила берётся консервативная линейная оценка
`BAND_HOP_S = 0.34` на полосу.

## 3. Полосы (bands) — авторская сетка, не снап движения

* **`N_BANDS = 5`**, центры равномерно: `bandY(k) = WORLD_H · (2k+1) / (2·N_BANDS)` →
  `54, 162, 270, 378, 486 lu` (k = 0 — у поверхности, 4 — у дна). Шаг `BAND_STEP = 108 lu`.
* Весь контент чанков (препятствия, рыба) **привязан к центрам банд** (`band: 0..4`) — читаемые,
  заучиваемые паттерны (главный провал жанра — непоследовательность распознавания паттернов).
  Тюлень между бандами движется **непрерывно** (§2), никакого снапа.
* Хитбоксы сущностей ≤ `BAND_STEP` по высоте (кроме явно «полутора-полосных» типов §6), чтобы
  между соседними бандами существовал проходимый коридор там, где это задумано автором чанка.

## 4. Скорость мира и прогрессия сложности

Базовый темп зависит от независимой координаты течения `worldD`.
Раскладка сложности выбирается заранее по координате чанка `d`; дебафф её не пересобирает.

### 4.1 Базовая скорость
```
baseSpeed(worldD) = 240 + (420 − 240) · min(1, worldD / 12000)
worldSpeed = baseSpeed(worldD) × chapterMultiplier × fishBuff × burst
worldD += worldSpeed · dt
```
Множитель главы: 1.00…1.14; gentle practice дополнительно ×0.8.
Положительные ускорения сохраняют прежний темп: рыба ×1.15, рывок ×1.35.
Сеть, истощение и хит-стан НЕ замедляют течение, фон, рыбу и угрозы.

### 4.2 Отставание и эффективная скорость тюленя
Целевое отставание (приоритет сверху): хит-стан 110 lu, мусор 96 lu,
истощение 64 lu, нормальное состояние 0. Пока отставание нарастает:
`lag += worldSpeed × (1 − retention) × dt`, с ограничением целевым значением.
Retention = 0 при стане, 0.4 при мусоре, 0.6 при истощении.
На пределе тюленя переносит течение, он остаётся видимым; это ограниченный игровой
эффект отставания, а не бесконечная потеря дистанции.

Возврат плавный, без overshoot:
`lag -= min((lag − targetLag) / 0.65, worldSpeed × 0.35) × dt`.
`d = worldD − lag`; `effSpeed = (d − previousD) / dt`.
Коллизии/очки используют d, а кинематика угроз и скролл — worldD.
Хит-стан продолжает запрещать манёвр и даёт прежний отброс по Y; i-frames сохраняются.
Пауза не вызывает step и останавливает обе координаты.

Измерение: [парное сравнение](seal-run-current-comparison.json), 780 пар забегов по
одинаковым expedition-2 трассам; [текущая матрица](seal-run-expedition-balance.json)
использует новые expedition-3 сиды. Бот не заменяет человеческое тестирование.

### 4.3 Окно сложности чанков
```
difficultyCeil(d) = 1 + floor(4 · min(1, d / RAMP_DISTANCE_LU))   // 1..5
difficultyFloor(d) = 1 + min(2, floor(3 · d / COURSE_LENGTH_LU)) // 1 → 2 → 3
```
Генератор (§9.3) выбирает чанки в окне `difficultyFloor(d) ≤ difficulty ≤ difficultyCeil(d)`; после чанка с флагом
`intense: true` — принудительно лёгкий (`difficulty ≤ 2`, не-intense) — «дыхание» по расписанию
трассы, одинаковое для всех (не реактивное на ошибки игрока).

## 5. Ресурсы: жизни и энергия

Энергия — условность аркады, не шкала кислорода. Тюлени дышат воздухом; рыба восстанавливает игровую энергию. UI и инструкции явно разделяют биологию и механику.

### 5.1 Константы
```
STARTING_LIVES = 3
STAMINA_MAX = 100 · STAMINA_DRAIN_PER_SEC = 4
FISH_STAMINA_RESTORE = 12
GRACE_WINDOW_MS = 2000 · STAMINA_EMPTY_SLOW_MULT = 0.6
STAMINA_REFILL_AFTER_LIFE = 50
```
Пассивный расход опустошает полный метр за 25 с → для поддержания нужна ~1 рыба каждые 3 с —
ограничение на раскладку рыбы в генераторе (§9.4).

### 5.2 Конечный автомат состояния тюленя
```
NORMAL ──stamina→0──────────────→ EXHAUSTED (отставание до 64 lu, дедлайн = t + GRACE_WINDOW_MS)
NORMAL/EXHAUSTED ──хищник──────→ HITSTUN (400 мс, манёвр запрещён, течение продолжается) → NORMAL (+i-frames §6.4)
EXHAUSTED ──рыба (stamina>0)───→ NORMAL
EXHAUSTED ──дедлайн истёк──────→ −1 жизнь; жизни>0 → NORMAL (stamina := 50); жизни=0 → DEAD
NORMAL/... ──жизни=0───────────→ DEAD (раунд завершён немедленно)
NORMAL/... ──d ≥ COURSE_LENGTH─→ FINISHED
```
* Жизни теряются **только** от хищника (§6.2) и от истечения grace-окна. Мусор и камни жизней не
  отнимают никогда.
* Потеря жизни от grace-окна i-frames **не** даёт (хищника не было); стамина после неё — 50.
* В HITSTUN пассивный расход энергии и течение продолжаются.

## 6. Три яруса препятствий — разная механика (v1, биом `coastal`)

Ярусы различимы **силуэтом, не только цветом** (SR-07, WCAG): хищник — живой силуэт с плавником,
мусор — угловатая рукотворная форма, камень — статичная масса от дна/навала.

### 6.1 Сводка
| Ярус | Типы v1 | Эффект | Жизни |
| --- | --- | --- | --- |
| Хищник | `orca`, `shark_white`, `shark_big` | −1 жизнь, хит-стан 400 мс + отброс, i-frames 1200 мс | да |
| Антропогенный | `ghost_net`, `plastic_cluster` | отставание до 96 lu, манёвренность ×0.65 на 1800 мс + расход стамины ×2.0 (pass-through зона) | нет |
| Естественный | `rock` | жёсткий отскок (40 lu) + стамина −5 | нет |

Ростер задаёт `core/fauna.js`: coastal/Atlantis — сельдевая и белая акулы;
Hawaii — галапагосская и тигровая; arctic — медведи, antarctic — морские леопарды.
Косатки есть во всех биомах; южный рисунок относится к паковому типу B1.
Атлантида — явная фантазия с молодым тевяком. Ссылки и ограничения интерпретации:
[биологические референсы](seal-run-anatomy-references.md).

### 6.2 Хищники — детерминированная кинематика (чистые функции мировой X)
Никакого ИИ/преследования в v1: движение хищника — функция его чанк-параметров и текущего
смещения мира. Все параметры — в данных чанка, фазы привязаны к `atLu` (не к wall-clock) →
одинаково для всех игроков при одном сиде.

**Чарджеры:** `x(worldD) = atLu − (CHARGE_REL / SPEED_MAX) ×
max(0, worldD − (atLu − 720))`. Предиктор бота и рендер используют тот же worldD.
Это детерминированная функция текущего состояния; она не останавливается вместе с
замедленным тюленем. Параметр d в исторической сигнатуре predatorPos означает worldD.

| Тип | Хитбокс | Кинематика | Чтение игроком |
| --- | --- | --- | --- |
| `orca` | круг r = 46 | Вертикальная синусоида между полосами: `y = bandY(band) + ampBands·BAND_STEP · sin(2π·(worldD − atLu)/ORCA_PERIOD_LU)`, `ORCA_PERIOD_LU = 900`, `ampBands ∈ {1, 2}` (из чанка). Скроллится с миром. | Вертикальная волна; одинаковая для всех устройств при одинаковом состоянии |
| `shark_white` | круг r = 30 | Держит свою полосу; движется НАВСТРЕЧУ: относительная скорость сближения `SHARK_CHARGE_REL = 180 lu/с` поверх скролла. | Встречный рывок; окно зависит от темпа главы, баффов, рывка игрока и отставания |
| `shark_big` | круг r = 42 | Как `shark_white`, но `SHARK_BIG_CHARGE_REL = 120 lu/с` + вертикальный боб ±0.5·BAND_STEP (та же синус-формула, период 600 lu) — фактически перекрывает ~1.5 полосы. | Медленнее, но толще — обходить дальше |

### 6.3 Антропогенный ярус — зоны-помехи (pass-through)
`ghost_net` (AABB 160×200 lu), `plastic_cluster` (AABB 140×120 lu). Столкновение не блокирует
движение: пока центр тюленя внутри зоны и `DEBRIS_SLOW_MS = 1800` мс после выхода —
отставание до 96 lu (§4.2), пределы вертикальной скорости/ускорения ×0.65,
расход энергии ×2.0. Повторный контакт **обновляет** таймер, множители не стакаются. Тематика: мусор не «охотится» — помеха, не атака
(перекличка с миссией sealrescue.info).

### 6.4 Хищник — удар, хит-стан, i-frames
При пересечении хитбоксов (вне i-frames): `−PREDATOR_LIFE_COST (1)` жизнь; **хит-стан
`PREDATOR_HITSTUN_MS = 400`** (манёвр игнорируется, отставание нарастает до 110 lu; течение движется); **отброс** — за время стана
тюлень плавно смещается на `PREDATOR_KNOCKBACK_LU = 40 lu` по Y от центра хищника (кламп границами
воды); **i-frames `INVULN_MS = 1200`** от момента удара (защита от двойного списания с одного
хищника; визуально — мигание, глушится `prefers-reduced-motion` до статичной прозрачности).

### 6.5 Камни — твёрдая геометрия
`rock` — AABB из данных чанка (типовой 120×160 lu, авторится от дна или как навал в полосе;
высота ≤ 2·BAND_STEP). Коллизия (круг тюленя × AABB):
1. Позиционное выталкивание по оси минимального проникновения (тоннелирование исключено фикс-шагом:
   максимальный сдвиг за тик ≪ размеров хитбоксов).
2. Отскок: смещение `ROCK_BOUNCE_PX = 40 lu` вдоль нормали + `vy := −vy · ROCK_RESTITUTION (0.5)`
   при вертикальной нормали; при горизонтальной (лоб) нормаль отскока — вертикальная, в сторону
   ближайшего свободного коридора (лint §9.4 гарантирует, что он есть).
3. `−ROCK_STAMINA_TAX (5)` стамины, с кулдауном `ROCK_TAX_COOLDOWN_MS = 300` на конкретный камень
   (чтобы скольжение вдоль камня не съедало метр за секунды).

## 7. Рыба — очки + стамина + бафф

| Тип | Очки (`fishPoints`) | Стамина | Бафф |
| --- | --- | --- | --- |
| `fish_small` | `FISH_SCORE_BASE = 1` | +12 | скорость ×1.15 |
| `fish_rare` (золотая) | `FISH_SCORE_RARE = 4` | +12 | скорость ×1.15 |

* Подбор: пересечение круга тюленя с кругом рыбы `FISH_PICKUP_R = 12 lu` (эффективный радиус
  подбора ≈ 36 lu — щедрый, «магнита» в v1 нет).
* Бафф: `FISH_SPEED_BUFF_MULT = 1.15` на `FISH_SPEED_BUFF_MS = 1500`; баффы складываются
  **длительностью, не силой** (очередная рыба добавляет 1500 мс к остатку), суммарный запас
  капится `BUFF_STACK_MAX_MS = 6000` — цепочка рыбы продлевает буст, но не позволяет «забанковать»
  минуту ускорения.
* Рыба неподвижна относительно мира (скроллится с трассой); позиция — банда + `atLu` из чанка.
  Декоративное покачивание — рендер-слой, на подбор не влияет.

## 8. Коллизии — авторитетны в sim-core

* Все геймплейные коллизии (хищник/мусор/камень/рыба) считаются в `core/sim.js` на фикс-шаге в lu.
  Тюлень — **круг `SEAL_R = 24 lu`** (спрайт ~96×48 — хитбокс заметно меньше визуала, прощающий,
  жанровая норма); формы остальных — §6/§7.
* **Рендер-слой не имеет права влиять на исход** (см. §12): Phaser Arcade Physics геймплейных
  коллизий не считает.
* Порядок обработки в тике: ввод → физика Y (§2.2) → течение `worldD` и дистанция `d` (§4.2) → коллизии (камни →
  выталкивание, затем хищники/мусор/рыба по возрастанию `atLu`) → ресурсы/автомат (§5.2).

## 9. Трасса: формат чанка + `generateCourse` (нормативно для SR-02)

### 9.1 Формат чанка (`core/chunks/coastal-*.js`)
Dependency-free ESM, без DOM/Phaser. Целые числа. Пример:

```js
// core/chunks/coastal-07.js
export const chunk = {
  id: 'coastal-07',        // уникален, стабилен (участвует в порядке реестра!)
  biome: 'coastal',        // v1: только 'coastal'; поле обязательно (задел v2)
  difficulty: 3,           // 1..5 — гейт по difficultyCeil(d)
  intense: true,           // кластер хищников → генератор поставит следом лёгкий чанк
  lenLu: 1200,             // CHUNK_LEN_LU — v1: у всех чанков одинаковая длина
  obstacles: [
    { type: 'rock',        band: 4, atLu: 260, w: 120, h: 160 },

  fish: [
```

`SURFACE`-задел (§1.6 дизайн-дока) живёт в `core/balance.js`: `SURFACE = { water: {VY_MAX, AY_MAX,
TAU_Y, …} }` — v1 заполняет только `water`, шаг физики читает параметры из активной среды.

### 9.2 Сид
```
courseSeedStr = season                       // ISO-неделя 'YYYY-Www' из currentSeason()
seedU32  = hashStr('seal-run-v1:' + courseSeedStr)   // FNV-1a — побитовая копия из core/alias.js
rnd      = mulberry32(seedU32)                        // побитовая копия из core/alias.js
```
Трасса недели = трасса до сброса доски (`pruneOldSeasons` уже недельный). На сервере `courseSeed`
берётся **из play-токена**, не от клиента (SR-10 п.2). Префикс `'seal-run-v1:'` изолирует сид от
любых других потребителей hash(season).

### 9.3 Алгоритм `generateCourse(seedStr, biome = 'coastal')`
1. Реестр чанков биома, **отсортированный по `id`** (порядок не зависит от порядка импортов —
   критично для Node/браузер-паритета).
2. Цикл, пока `Σ lenLu < COURSE_LENGTH_LU (36000)`; на итерации: `eligible` = чанки с
   `difficultyFloor(dCur) ≤ difficulty ≤ difficultyCeil(dCur)` (§4.3), `id ≠ предыдущему`, а если предыдущий был
   `intense` — только `difficulty ≤ 2 && !intense`. Выбор: `eligible[floor(rnd() ·
   eligible.length)]` — **ровно один вызов `rnd()` на чанк**, больше RNG нигде (дисциплина
   счётчика бросков — как в `makeParts`).
3. Трасса обрезается ровно на `COURSE_LENGTH_LU`; сущности с глобальной позицией за финишем
   отбрасываются. Финишная черта — на `COURSE_LENGTH_LU`.
4. Возврат: плоские списки сущностей с глобальными `atLu`; **бюджеты рыбы** до дистанции d —
   `fishCountBudget(course, d)` / `fishPointsBudget(course, d)` (точные, по `atLu` каждой рыбы,
   с зазором досягаемости `FISH_REACH_SLACK_LU = 50`) — их использует серверная сверка (§10.3).
5. Golden-hash трассы (стабильная JSON-сериализация → FNV-1a) — предмет parity-теста SR-14
   (повтор + Node↔браузер).

### 9.4 Обязательные инварианты библиотеки (chunk-lint, гейт CI в SR-02)
1. **Проходимость:** между последовательными «форс-манёврами» (позициями, где текущая полоса
   становится смертельной/блокированной) горизонтальный зазор
   `ΔLu ≥ ceil(SPEED_MAX · FISH_SPEED_BUFF_MULT · (REACT_S + k · BAND_HOP_S))`, где `k` — число
   полос манёвра, `BAND_HOP_S = 0.34` (§2.2), `REACT_S = 0.25`. Считается на худшем случае
   (плато + бафф) → честно на любой дистанции. «Никогда не несправедливо при первой встрече».
2. **Коридор у камней:** в любом вертикальном срезе трассы суммарная твёрдая геометрия оставляет
   свободный проход ≥ `3·SEAL_R` (72 lu).
3. **Питание:** в любом скользящем окне 30 с на плато (~12600 lu) — досягаемая рыба со стаминой
   ≥ `1.2 ×` пассивного расхода окна (120 стамины → ≥ 12 рыб) — метр обязан быть удерживаемым
   без идеальной игры.
4. **Бюджет очков рыбы:** суммарные `fishPoints` трассы ≤ `FISH_POINTS_BUDGET_MAX = 400` — иначе
   формула очков (§10.2) может пробить Zod-кап `score ≤ 100000`.
5. Библиотека v1: **15–25 чанков**, только `biome: 'coastal'`, `lenLu = 1200` у всех; ≥ 4 чанков
   `difficulty: 1` (старт трассы выбирает только из них — §4.3 при `d = 0`).

## 10. Сессия, очки, сабмит

### 10.1 Завершение раунда
Раунд кончается первым из: **DEAD** (жизни = 0), **FINISHED** (`d ≥ COURSE_LENGTH_LU`),
**таймаут клиента** `MAX_COURSE_MS = 150000` (страховка; фиксируется текущее состояние).
Результат: `distance_m`, `fishCollected` (штук), `fishPoints`, `livesRemaining`, `durationMs`.

### 10.2 Формула очков (производная, distance-first)
```
score = SCORE_PER_M · distance_m + SCORE_PER_FISH_POINT · fishPoints + SCORE_PER_LIFE · livesRemaining
SCORE_PER_M = 100 · SCORE_PER_FISH_POINT = 20 · SCORE_PER_LIFE = 300
```
Максимум главы: `100·900 + 20·400 + 300·3 = 98 900`. Пять глав дают максимум
494 500; Zod-кап Seal Run — 500 000. Hunter сохраняет свой прежний кап 100 000.
Дистанция доминирует; при равной дистанции решают рыба и сохранённые жизни.

### 10.3 Контракт сабмита SR-10/SR-20
Существующие поля `game, score, durationMs, seed, token` дополняются обязательным для Run
массивом `rounds` (1…5). Глава: `distanceM` 0…900, `fishCollected` 0…400,
`fishPoints` 0…400, `livesRemaining` 0…3, `durationMs` 3000…150010.
Все предыдущие главы должны иметь 900 м и хотя бы одну жизнь. Последнюю можно закончить
досрочно. Таймаут — не финиш. Сервер выводит `levelsCompleted`, общую дистанцию, рыбу
и `courseSeed`; клиент не задаёт эти агрегаты как истину.

Токен /start (TTL 30 минут) подписывает `g,t,n,s,cs,rv,p`: игру, время, nonce,
ISO-неделю, seed курса (неделя), rules version и player seed. Проверка и запись используют
неделю токена, даже после понедельника 00:00 UTC. Старый сезон получает часовой grace period.
Одноразовые nonce и rate limits живут в памяти одного процесса, как у Hunter.

Для каждой главы сервер вызывает `generateRound(token.cs,index)`. Максимальная возможная
скорость для нижней оценки времени: `420 × 1.15 × 1.35 × roundSpeed(index)`;
допуск округления 100 мс. Реальная скорость обычно ниже из-за рампы, стоимости/кулдауна рывка
и препятствий. Возраст токена ≥3 с, суммарное игровое время ≤ возраст+1000 мс.
Количество рыбы и очков не превышает бюджет достигнутого участка (+76 lu: радиус подбора 36 + округление метра 40).
Число редких рыб `(fishPoints-fishCollected)/3` должно быть целым и достижимым;
сервер отдельно ограничивает обычный улов. Итоговый score точно равен сумме формул глав;
durationMs равен сумме длительностей с допуском 5 мс.

Это проверка правдоподобия по бюджетам, не replay верификация ввода.

## 11. Телеграфирование и честность паттернов (обязательные правила авторинга)

Выжимка жанровых best practices (см. источники в PR SR-01), закреплённая как правила:

1. **Ничто не убивает из-за экрана:** хищник входит в поле с правого края с временем сближения
   ≥ ~1.1 с в худшем случае (плато + бафф; `SHARK_CHARGE_REL` подобран под это; орка скроллится
   с миром — видна ещё дольше). Порог валидирует харнесс SR-04.
2. **Паттерны консистентны:** один и тот же тип ведёт себя одинаково всю игру (никаких
   «иногда орка дёргается быстрее»); вариации — только авторские, через параметры чанка.
3. **Новизна — по расписанию сложности:** типы препятствий вводятся difficulty-гейтом чанков
   (§4.3), первый экземпляр нового типа игрок встречает в «разреженном» контексте (лint-правило:
   в чанках `difficulty: 1..2` не более одного хищника на чанк).
4. **«Дыхание»:** после `intense`-чанка — гарантированно лёгкий (§4.3), позиционно одинаково
   для всех.
5. **Различимость ярусов без цвета** — силуэт (§6), плюс тинт из semantic-токенов (SR-06/SR-07).

## 12. Ограничения рендер-слоя Phaser 4 (вход для SR-05)

* **Phaser ≥ 4.1.0 «Salusa»** (апрель 2026), vendored ESM
  (`public/games/seal-run-v1/vendor/phaser.esm.js`): именно 4.1.0 починил ESM-билд — default
  export (`import Phaser from …`) и `Class`-конструктор. Документация — docs.phaser.io.
* Сцена `Play` держит **accumulator фикс-шага**: `update(time, delta)` набирает `delta` и гоняет
  `core/sim.js` шагами `SIM_DT`, рендер интерполирует. Phaser-таймеры/твины — только для декора.
* **Arcade Physics не авторитетна:** спрайты позиционируются из sim-состояния; никакие
  Phaser-коллайдеры не меняют геймплей. Object pooling для рыбы/препятствий — обязателен (SR-05).
* Сущности спавнятся в рендер, когда их `atLu` входит в окно `[d − 200, d + FIELD_W + 200]`,
  деспавнятся за левым краем; sim при этом оперирует всеми сущностями окна коллизий (± экран).

## 15. Экспедиции, рывок и представление (SR-15…SR-20)

Пять биомов: coastal → atlantis → tropical (Hawaii) → arctic → antarctic.
Сид главы: `expedition-3:ISO-week:index`; скорость `1 + index × 0.035`.
Тренировка выбирает любую стартовую локацию и seed; gentle pace умножает скорость на 0.8.
Space: стоимость 18 энергии, множитель скорости 1.35 на 800 мс, cooldown 4000 мс.
Пауза не двигает sim-время. После 900 м sim заморожена, выход спрайта длится 950 мс
(180 мс при reduced motion), затем HTML-результат. Каждая новая глава начинает с 3 жизнями
и 100 энергии. Таймаут 150 с завершает главу как dead без levelsCompleted.
Боб рыбы — render-only: small ±5 lu, rare ±8 lu; при reduced motion 0.
Актуальные арт/UX/хранение и отчёт баланса: [game-seal-run.md](game-seal-run.md).

### Surface hazards (introduced in expedition-2, retained in expedition-3)

boat_propeller: stationary band-1 circle, center y=162, radius 32 lu. Collision removes
one life with the same stun/i-frames as predators; the swept disc is outlined in the art.
The hull/shaft is decorative. Placement is deterministic after flattening chunks, with
420 lu clearance from other upper-water threats and 150 lu from band-1 fish. Surface bear
centers are separated by at least 420 lu across chunk boundaries. The generator consumes
no extra RNG draws. Current rules version is expedition-3, shared by server and browser.
Full-length submerged hulls are decorative; only the rotating motor disc removes a life.
