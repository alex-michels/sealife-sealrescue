# Игра «Seal The Hunter» (seal-hunt-v1)

Мини-игра про тюленя: лови рыбу за 60 секунд. Vanilla **HTML/CSS/Canvas2D**, без фреймворка и сборки —
файлы лежат как есть в `public/games/seal-hunt-v1/` и отдаются статикой. Встраивается на странице
`app/(frontend)/[site]/[locale]/games/[slug]/page.tsx`; язык интерфейса передаётся через `?lang=ru|en|de`.

## Структура файлов
```
public/games/seal-hunt-v1/
  index.html                # разметка: HUD, canvas, overlay, board
  style.css
  game.js                   # игровой цикл, состояние, ввод-вывод
  i18n.js                   # словарь ru/en/de; язык из ?lang=, window.SealI18n.{lang,t,dict}
  manifest.webmanifest      # PWA-манифест
  sw.js                     # service worker (network-first)
  favicon.svg
  core/
    alias.js                # анонимная идентичность игрока (seed) + рендер имени
    leaderboard.js          # клиент лидерборда (fetch к /api/leaderboard*)
    sim.js                  # DOM-free ядро симуляции (stepSeal, spawnTick) — общее с харнессом
    balance.js              # тюнинг темпа/баланса + VIEW_CFG (фикс. поле 16:9 / 9:16)
    input.js                # клавиатура/тач
    theme.js                # цвета/токены под бренд
  entities/{seal,prey}.js   # сущности: тюлень, добыча
  render/scenery.js         # процедурная сцена + опц. статический бэкдроп + бордюр (см. ниже)
  assets/                   # опц. бэкдроп-арт backdrop-{landscape,portrait}.{avif,webp,jpg} + README
  tools/                    # dev-only (не грузятся игрой): fairness-sim, compare-variants,
                            #   encode-image (PNG→avif/webp/jpg), make-placeholder-backdrop
```

## Fairness (честность) — SH-12: фиксированное поле 16:9 / 9:16 («равный горизонт»)
Играбельное поле **фиксировано**: **960×540 lu (16:9)** в ландшафте, **540×960 (9:16)** в портрете
(`VIEW_CFG.aspect`, `computeWorld`) — экран поле не меняет вообще. Все ландшафтные игроки играют
в байт-идентичном мире, все портретные — в байт-идентичном мире; при единой доске (SH-11) это
полный «равный горизонт», как у Seal Run. Инварианты SH-02b остаются основой: скорости/размеры
тюленя и рыбы const, **плотность добычи const** (оба фикс-поля равноплощадны → prey-cap одинаков).

**Замер (2026-07-03, seed 0, N=80, 16 профилей):** все ландшафты — 92.2 catch/round
(байт-идентично), все портреты — 93.0; **разброс 0.8%** — единственная оставшаяся разница =
форма 16:9-поля vs 9:16-поля, принята осознанно (доска единая). До SH-12 (кламп 2:1) разброс
был 5.5%: короткая ось держалась 540 lu, длинная следовала экрану с клампом 2:1 — бот показал,
что поле длиннее ~2:1 измеримо легче (длинное узкое поле выгодно охотнику), а внутри ≤2:1
оставался спред по форме.

**Цена решения (принята осознанно, Roadmap SH-12):** экраны не ровно 16:9/9:16 получают
диегетический бордюр «край бухты» (`render/scenery.js`), а не чёрные полосы — теперь ЧАЩЕ, чем
при клампе: 16:10/4:3-ландшафты — **дно снизу + поверхность с волнами/лодкой сверху**,
ультравайд и портретные планшеты — **стены водорослей** по бокам, вытянутые телефоны —
дно+поверхность. `initBorder` ветвится по РЕАЛЬНЫМ зазорам (`ox`/`oy`), не по ориентации —
новые случаи переиспользуют те же строители полос. Рендер бордюра разбит на слои за/перед полем
(`drawDeepBackdrop` + `drawBorderBack` → поле → `drawBorderFront`).

* **Ядро симуляции вынесено в `core/sim.js`** (физика тюленя + спавн), без DOM/рендера — игра и тест
  гоняют один и тот же код. Механика/спавн/анимации при SH-12 не менялись — только вью-математика
  (golden-трейс QA-30 не изменился: FHD и раньше давал мир 960×540).
* **Тест честности — `tools/fairness-sim.mjs`:** бот-«жадный охотник» играет реальное ядро на профилях
  экранов (small → 32:9 → tall) и печатает catch-rate ± sd. `node tools/fairness-sim.mjs 80`
  (`ASPECT=2` — эксперимент с другим фикс. аспектом). Логика (бот/раунд/профили/seeded RNG) — в
  `tools/fairness-lib.mjs`, её же гоняет **CI** (QA-30/31): `tests/unit/sim-golden.unit.spec.ts`
  (golden run: seed → идентичный трейс; осознанное обновление `UPDATE_GOLDEN=1`) и
  `tests/unit/fairness.unit.spec.ts` (6 профилей × 12 раундов: разброс ≤5%, отклонение профиля
  ≤3% — ужато после SH-12; фикс. поле закреплено ассертом на всех профилях). Полный прогон —
  вручную при изменении баланса.

Раунд всегда **60 секунд** (`ROUND_MS`). Доска **единая** — деление `desktop`/`mobile` снято
(решение 2026-07-03, SH-11, консистентность с Seal Run); после SH-12 внутри доски осталась только
разница форм 16:9 vs 9:16 = **0.8%** (замер выше) — принято осознанно.

## Добыча: вид и анимация (`entities/prey.js` + `core/theme.js`)

Добыча — **100 % процедурный векторный флэт-арт** (`drawFish` / `drawStar` / `drawSquid`),
а НЕ картинки. 11 видов делят 5 силуэтов (`round` / `slim` / `eel` / `squid` / `star`) и
красятся брендовыми схемами `PALETTE.fish` (`theme.js`). Преимущество против PNG-спрайтов:
рисуется чётко на **любом радиусе и DPR**, **свободно перекрашивается**, не грузит ассеты,
держит `prefers-reduced-motion` — и **совпадает по стилю с тюленем** (тоже вектор).

* **Ориентация по движению — смотрят по ходу, но НЕ переворачиваются «брюхом вверх»** (в отличие
  от тюленя, который перекатывается). `f.ang` плавно доворачивается к вектору скорости
  (`updatePrey`, темп `PREY_TURN`); `drawPrey` раскладывает курс на **липкий лево/право-флип**
  (`f.face`, гистерезис по `cos(ang)`: около вертикали держит прошлую сторону → нет мерцания на
  вертикальных заплывах) + **питч** (наклон носа): `scale(face,1)` затем `rotate(pitch)`, где
  `pitch = atan2(sin·ang, face·cos·ang) ∈ (−90°,90°)` — курс воспроизводится, а **брюхо всегда
  снизу**. **Кальмар и морская звезда** не «мордой по +x» (вертикальная мантия / радиальное тело),
  поэтому **не доворачиваются** — стоят ровно, двигаются только их части. Ориентация — не под
  `reduced-motion` (это поворот, не «анимация»); `f.ang`/`f.face` в физику/коллизии/баланс не
  входят → честность не меняется.
* **Анимация плавания — трансформами, не кадрами** (`drawPrey` → `anim`): рыбы **машут хвостом**
  (`tailWag` — хвостовой плавник поворачивается вокруг основания), **кальмар шевелит щупальцами**
  (`tentPhase`/`tentAmp` — бегущая волна по щупальцам), плюс idle-покачивание тела (`wig`) и
  squash (`sclY`); `tailKick` — хвост шире на рывке-бегстве (C-start). Амплитуда махов/волны
  масштабируется силой плавания (`swim`), под `prefers-reduced-motion` всё выключено. Поэтому
  «анимированные» добычи **не требуют GIF/APNG или спрайт-листов**.
* **Читаемость на бэкдропе (reef, PR #32).** Каждая добыча рисуется с **тёмным
  separation-edge** (`OUTLINE` — увеличенный силуэт сзади) + **светлым верхним rim**: тёмный
  край отделяет на ярком рифе, светлый rim — на тёмной глубине. Тело — **контршейдинг**
  (тёмная спина → светлый живот) как у тюленя; усилены силуэты (спинной плавник). Схемы в
  `PALETTE.fish` разнесены по тону/светлоте, чтобы виды различались и формой, и цветом
  (WCAG: цвет — не единственный носитель смысла).
* **Призовая рыба `goldie`** (схема `coral`) помечена `prize: true` → более яркий rim +
  спаркл; редкая «золотистая» добыча выделяется на фоне косяка.
* **Поверхность и боковые стены (визуальный контракт SH-12 follow-up).** Добыча **не клипается**
  к сырому прямоугольнику поля: у левого/правого края и снизу она может дорисоваться в бордюр и
  растворяется `EDGE_FADE_LU` перед safety-cull. Прячут её только диегетические слои: боковые
  **kelp-walls рисуются в `drawBorderFront` поверх добычи и тюленя**, поэтому оба визуально
  остаются за стеной бухты. На ultra-tall экранах с верхним бордюром (воздух) добыча **клипается
  по ватерлинии** (`worldY ≥ 0`) и рисуется на **своей реальной позиции**, растворяясь по
  `EDGE_FADE_LU` по мере всплытия, а **кольцо-рябь** отмечает пересечение поверхности — рыба
  плавно «ныряет» под воду, не «летит» в воздух и **не превращается в ловимый на вид фантом**
  под водой (тюлень закламплен в поле, `core/sim.js`; коллизия проверяет реальную позицию —
  раньше зеркальный спрайт создавал недостижимую цель, и поимка не засчитывалась). Рендер честен
  относительно коллизии. Рендер-only: физика/спавн/кулл/поимка не тронуты.
* **Контрактный замок текущего состояния** (запрос владельца, 2026-07-03): визуал закреплён
  `tests/e2e/game-visual-borders.e2e.spec.ts` (**7 контрактов**, real-pixel: kelp-walls поверх
  тюленя и добычи; no-clip по бокам; поверхность без «рыбы в воздухе» и без фантома; матрица
  бордюров по ориентациям 16:10/9:19.5 → небо+дно, 3:4/21:9 → стены; полевые водоросли поверх
  фона но под добычей; фейд-кривая `EDGE_FADE_LU`; рябь-«флоп-плюх» дифференциально), краевая
  механика — `tests/unit/seal-hunt-prey-edges.unit.spec.ts` (спавн 4-edge shuffle-bag ±20 строго
  внутрь; edge-push возвращает со всех 4 сторон, не доводя до кулла ±40; кулл −39/−45/NaN).
  Полный список — worklog §9.
* **Менять вид** — только `drawFish`/`drawStar`/`drawSquid` и `PALETTE.fish`; геометрия
  спавна/коллизий и баланс **не трогаются** (механика честности — отдельно, см. Fairness).
  После правки рендера/схем — **бампать `CACHE`** в `sw.js` (файлы SW-кэшируются).

## Service worker (`sw.js`)
**Network-first**, scoped к `/games/seal-hunt-v1/`. Кэш `seal-hunt-static-v<N>` (версия бампается на
каждое изменение ассетов — смотреть актуальное значение `CACHE` в `sw.js`, не полагаться на число ниже):
на каждый успешный GET сеть обновляет кэш; offline → отдаётся последняя копия. Так апдейты всегда
«доезжают» (важно при деплое из `main` — игрок не залипает на старой версии). Старые кэши чистятся на
`activate`. `/api/*` НЕ кэшируется.

## Анонимная идентичность игрока (`core/alias.js`)
- **`seed`** — случайный opaque-идентификатор, хранится в `localStorage` (`getSeed`/`setSeed`). Это
  **не** PII и **не** source of truth для очков — только стабильная локальная идентичность, чтобы строки
  игрока за неделю дедуплицировались. Source of truth (очки, доска) — **сервер**.
- Имя строится детерминированно из `(seed, game)` PRNG (`makeParts`) → набор индексов частей; рисуется
  на языке зрителя (`renderName(parts, lang)`). Имена варьируются по шаблонам (Adj/Mod/Pref-/-Suf + Noun),
  пространство ~40k без чисел.

> ⚠️ **Списки имён, `PATTERNS`, `mulberry32` и порядок бросков ДОЛЖНЫ совпадать** между
> `core/alias.js` (клиент) и `src/endpoints/leaderboard.ts` (сервер) — иначе имя на старте разойдётся с
> доской. В серверном файле об этом есть «KEEP IN SYNC».

## Лидерборд (`core/leaderboard.js` ↔ `src/endpoints/leaderboard.ts`)
Server-authoritative. Поток раунда:

1. **Старт:** `startRound(gameSlug)` → `GET /api/leaderboard/start?game=` → получает **play-token**.
   Токен берётся именно на старте, чтобы серверу было видно реально отыгранное время.
2. **Сабмит:** `mountAfterPlay()` → `POST /api/leaderboard` c `{game, score, durationMs:60000, seed, token}`.
   Токен одноразовый.
3. **Чтение/пагинация:** `GET /api/leaderboard?game=&page=` (страница 50, скролл до строки игрока,
   «показать ещё» до 500).

> **Устойчивость:** `startRound` ретраит запрос токена один раз; если сабмит всё же не прошёл (потерянный
> play-token), `mountAfterPlay` показывает доску в **режиме чтения**, а не «доска недоступна». Имена строк
> рендерятся на языке зрителя (`ru`/`en`/`de`) из частей — сервер хранит индексы + canonical EN-alias.
> Грамматика — по локали: DE и RU склоняют прилагательное по роду существительного (поля `gde`/`gru`
> у NOUN в `core/alias.js`; DE — суффикс-голова, RU — ведущее сущ.). Добавляя NOUN, добавь EN-строку в
> `NOUN_EN` (`endpoints/leaderboard.ts`) на ту же позицию — длина/порядок списков обязаны совпадать.

> **Согласованность ранга:** строка «Вы: #N из M» берётся из РЕАЛЬНОЙ строки игрока в показанной доске
> (единый источник правды в `mountAfterPlay`), поэтому не расходится с подсвеченной строкой. Раньше
> сервер давал ранг competition-стилем (равные очки → один ранг), а таблица — порядковый (1,2,3…), и при
> ничьей сверху номера расходились (#4 в подписи vs #5 в строке). `total` защищён от рассинхрона снизу.

Контракт endpoints, коды ошибок — в [api.md](api.md).

### Анти-чит (SH-08) — на сервере
- **Play-token:** подписанный HMAC (секрет = `PAYLOAD_SECRET`), привязан к `game`, с временной меткой.
  Проверяется подпись, возраст (сыграно ≥ 40 c — `MIN_PLAY_MS`, запас под cold-start dev/Turbopack;
  токену ≤ 30 мин), одноразовость (nonce в памяти).
- **Плаузибилити-капы:** `durationMs` ∈ 50000..70000; `score` ≤ ⌈сек·3⌉+8 (потолок поимок/с).
- **Rate-limit:** ≤ 30 запросов/мин с IP — **transient, в памяти, IP в БД не хранится**.
- Всё это поднимает планку: счёт нельзя залить, не «прожив» раунд; токен — на один раз.

### Идентичность и сезоны
- **`season`** = ISO-неделя (`YYYY-Www`); доска **сбрасывается еженедельно**. `resetAt` = ближайший
  понедельник 00:00 UTC.
- **`playerKey`** = `sha256(seed:game:season)` (24 hex) — недельный односторонний ключ для дедупа строки;
  ротируется и удаляется при сбросе → долговременного идентификатора нет.
- Одна строка на `(game, playerKey, season)`, хранится **максимум** счёта. Коллизия base-имени с
  другим игроком → суффикс уникальности («Triton Loaf 2»).
- **Ленивая очистка:** прошлые сезоны удаляются (не чаще раза в час на процесс) — минимизация данных.

## EU-чистота
Нет PII: ни email, ни аккаунтов, ни сырого seed на сервере, IP не хранится. `game-scores` — анонимная
коллекция (см. [data-model.md](data-model.md)). Это позволяет лидерборду работать до появления аккаунтов
(требование COMPLIANCE: лидерборды до аккаунтов — анонимные/псевдонимные без email).

## Публичный alpha-тест (sealthehunter.online) — standalone-режим
Игра + лидерборд отдаются отдельным публичным тестом тем же деплоем из `main`, с allowlist маршрутов
(наружу — только игра и `/api/leaderboard*`, без `/admin` и прочего API). На этом домене Caddy отдаёт
игру **с корня** (rewrite `/* → /games/seal-hunt-v1/*`). Инфраструктура — [DEPLOYMENT.md](DEPLOYMENT.md) §4–7.

**Standalone vs встраивание (один код, без дублирования).** Игра определяет, что открыта **не во фрейме**
(`STANDALONE = window.self === window.top`, в `i18n.js`). Во фрейме (встраивание на sealife.*) поведение
прежнее. В standalone дополнительно:

* **Переключатель языка RU/EN/DE** на стартовом/финальном экране (`#langSwitch`). `window.SealI18n.setLang(l, persist)`
  меняет язык на лету: `applyStatic()` + колбэк `onLangChange` (его ставит `game.js`) перерисовывает
  приветствие, интро, заметку и доску (`relocalizeBoard` в `core/leaderboard.js` — без повторного сабмита).
* **Стартовый язык:** `?lang=` → сохранённый выбор (`localStorage` `seal_hunt_lang`) → язык браузера
  (ru→ru, de→de, иначе en — как `pickLocale` в `src/proxy.ts`) → `ru`. Запись в `localStorage` —
  **только после явного клика** по переключателю (COMPLIANCE: язык хранить лишь после явного выбора).
* **Заметка про альфа-тест** (`#alphaNotice`, ключ `alphaNotice`) + **контакт** `feedback@sealthehunter.online`
  (`#feedbackInvite`, ключ `feedbackInvite`) — на стартовом И финальном (с лидербордом) экране. Email —
  отображаемый контакт оператора, не сбор email (COMPLIANCE).

Все эти элементы скрыты во встраиваемой версии (`hidden`, снимается только при `STANDALONE`). Правки —
в `public/games/seal-hunt-v1/` (`i18n.js`, `index.html`, `game.js`, `style.css`); после правки ассетов
бампать `CACHE` в `sw.js` (см. текущее значение в файле — версия растёт с каждым визуальным изменением;
SW также не кэширует `/api/`).

## Обложка / фон стартового экрана (`cover.jpg`) + превью ссылки (OG)

`public/games/seal-hunt-v1/assets/cover.jpg` — арт-обложка (лежит в `assets/` рядом с бэкдропом),
используется **дважды**:

1. **Затемнённый фон оверлея** (стартовый + финальный экран, в **обоих** режимах — standalone и
   встраивание). В `style.css` у `#overlay` фон подаётся через **`image-set()`**: браузер берёт
   меньший формат из лесенки **AVIF → WebP → JPEG** (те же форматы, что у бэкдропа), а строка
   `url("assets/cover.jpg")` перед `image-set` — фолбэк для браузеров без `image-set`/`type()`. Поверх —
   градиент-скрим `linear-gradient(180deg, rgba(11,40,50,.62), rgba(11,40,50,.76))`.
   * **Притемнение / читаемость текста** — две alpha в градиенте: верх `.62`, низ `.76`. **Больше =
     темнее** (текст контрастнее), меньше = арт ярче. Подстраивается под вкус.
   * **`center top`** (не `center`) — чтобы заголовок на самой обложке не обрезался сверху на широких
     экранах. `background-size: cover` всегда кадрирует под вьюпорт; верх якорим → обрезается нижняя
     вода, а не заголовок.
   * **Портрет/мобайл:** широкая landscape-обложка режет заголовок по бокам, позицией не лечится.
     Поэтому на портрете (`@media (orientation: portrait)`) — отдельная **портретная** обложка
     `cover_mobile.{avif,webp,jpg}` (тоже через `image-set`; ~9:16, без вшитого заголовка — его даёт
     `<h1>`; тюлень и рыбы в центральной зоне). **Портретная обложка — только фон в браузере, в OG не
     используется** → формат свободный (AVIF/WebP выгоднее JPEG). Затемнение — те же alpha в градиенте
     медиа-запроса. Нет файла → останется тёмный градиент. (OG-превью всегда берёт landscape `cover.jpg`.)
2. **Превью при шаринге ссылки** (Open Graph + Twitter) — мета в `<head>` `index.html`: абсолютные URL
   на `https://sealthehunter.online/assets/cover.jpg` (→ `/games/seal-hunt-v1/assets/cover.jpg` через
   catch-all в `deploy/Caddyfile`), `summary_large_image`.

**Требования к OG-файлу (`cover.jpg`):** идеально **1200×630** (1.91:1), **JPG/PNG** (не WebP/AVIF —
часть скрейперов не берёт их для OG; это ограничение **только для OG-картинки** — фон оверлея в браузере
подаётся `image-set`-лесенкой AVIF/WebP/JPEG), желательно **< 300 КБ**; заголовок/тюлень держать в
центральной safe-zone (края кадрируются и фоном, и соц-превью). Текущий файл — **1200×630**,
`og:image:height` = **630**.

**Заменить арт:** положить исходные PNG `cover-src.png` (ландшафт) и `cover-mobile-src.png` (портрет) в
**`assets/`** (оба под `**/*-src.png` в `.gitignore` — большие исходники не коммитятся) и прогнать
конвертер `tools/encode-image.mjs` (`--out assets`) → `assets/cover.{avif,webp,jpg}` (ширина 1200) и
`assets/cover_mobile.{avif,webp,jpg}` (ширина 1080); команды — в `assets/README.md`. Затем **забампить `CACHE`** в `sw.js`. Если у ландшафта меняются
пропорции — поправить `og:image:width/height` в `index.html`. Проверить превью через Facebook Sharing
Debugger / X Card Validator (форс ре-скрейп).

## Фон игрового поля (бэкдроп) + анимированная сцена (`render/scenery.js`)

Опционально игровое поле рисуется поверх **статической картинки** (напр. AI-арт: туманная коралловая
сцена) вместо полностью процедурной воды. Включается само, если в `assets/` есть файлы; нет файлов →
процедурная сцена как раньше (см. Fairness), **без изменений и без ошибок**. **Геймплей это НЕ трогает:
ни управление, ни физика тюленя, ни добыча, ни коллизии, ни баланс/честность — меняется только вид**
(в diff против `main` файлы `core/{sim,input,balance}.js`, `entities/{seal,prey}.js` не затронуты).

### Модель «одна сцена»
**Одна картинка рисуется на ВЕСЬ вьюпорт** (поле + бордюр >2:1 / >1:2), поэтому арт читается как единая
сцена. Поверх — **анимированный слой**, который и оживляет, и **показывает границы поля**: по бокам —
**колышущиеся стены водорослей** (kelp-walls); сверху — **рябь поверхности + лодка** (граница вода↔воздух);
снизу — **водоросли/трава со дна**. Статичные камни/кораллы даёт АРТ, всю анимацию — игра. Тюлень
по-прежнему заперт в поле (2:1-кламп), честность не меняется — шире только визуал.

### Файлы и загрузка
```
assets/
  backdrop-landscape.{avif,webp,jpg}   # ландшафт/квадрат — рисуй УЛЬТРАШИРОКИМ (~21:9)
  backdrop-portrait.{avif,webp,jpg}    # портрет — рисуй УЛЬТРАВЫСОКИМ (~9:21)
  README.md                            # как добавить арт + конвейер кодирования
```
- `initBackdrop()` (зовётся на старте из `game.js`) пробует **AVIF → WebP → JPEG**, берёт первый
  загруженный; `await img.decode()` до использования → не мигает полузагруженным (пока не готово — видна
  процедурная вода). `isBackdropActive(world)` выбирает картинку по ориентации.
- **Конвейер кодирования** `tools/encode-image.mjs`: любой PNG/JPG → оптимизированные AVIF+WebP+JPEG
  нужной ширины (+опц. blur). Универсальный — кодирует и `cover.jpg`/`cover_mobile.jpg`. Команды — в
  `assets/README.md`. Плейсхолдеры генерит `tools/make-placeholder-backdrop.mjs`. Исходники (и бэкдропа,
  и обложек) лежат в `assets/` как `*-src.png` — в `.gitignore` (`**/*-src.png`; большие, не в репо).

### Якорение / кроп (`drawBackdropFullscreen`)
Cover-fit на весь вьюпорт, по умолчанию **по низу** (дно/кораллы всегда на полу — водоросли растут из
реального дна; срезается верхняя открытая вода). Исключение — **портрет без бордюра** (≤2:1, поле
заполняет экран): арт **приподнят** на `PORTRAIT_BOTTOM_CUT` (~11% высоты вьюпорта), чтобы срезать самый
тёмный «абисс» у дна — риф виден у пола, но «не так глубоко». **Портрет с бордюром (>2:1)** и **ландшафт**
— ровный нижний якорь без кропа.

### Граница вода/воздух и маркеры границ
Над поверхностью (верхний бордюр высокого портрета) рисуется **небо/воздух** (`drawSkyBack` — в обоих
режимах), чтобы линия воды была настоящей границей вода↔воздух: светлый воздух сверху, вода (арт) снизу,
лодка на поверхности. Линия поверхности (`drawWaterline`) намеренно **приглушена**. В режиме бэкдропа
бордюрные функции рисуют **только анимированные детали**, а непрозрачные заливки и статичный декор
**пропускают** (арт виден насквозь): `drawBorderBack(..., bd)` → `drawSideWalls`/`drawSkyBack`/`drawSeabed`
с флагом `bd`. Водоросли поля укоренены **на дне экрана** (`bottomExtra` в `drawBackground` — протягивает
их вниз через нижний бордюр к реальному дну на >1:2-экранах) и сделаны длиннее.

### Цвет водорослей (`makeKelpColor` / `kelpStroke`)
Подводная зелень в **разных тёмных «ступенях»** (случайная базовая светлота), с градиентом по стеблю
(темнее у корня → светлее к кончику). ~1/3 стеблей **переливаются** (shimmer): медленный дрейф **светлоты
и насыщенности** — **тон зафиксирован в зелёном диапазоне (hue 142–172)**, чтобы блик не уходил в
синий/серый; насыщенность с полом (не сереет), кончик с потолком (не выцветает). Под `prefers-reduced-motion`
shimmer выключен. Применено к водорослям поля, стенам бордюра и траве.

### Тинт глубины на весь экран (`drawWaterGradient`)
Полупрозрачная вертикальная заливка собственного градиента воды на **весь вьюпорт** (поле + подводные
бордюры): мягкий свет у поверхности → лёгкое затемнение к дну → **единый тон глубины везде**, персонажи
по-прежнему «выскакивают» поверх. В режиме бэкдропа заменяет полевые surface-glow/depth-vignette.
Кэшируется (статичен при фикс. высоте вьюпорта) — строится раз на ресайз.

### Производительность
- **Кэш бэкдропа:** `drawBackdropFullscreen` собирает cover-fit картинку в **offscreen-canvas в
  backing-store разрешении** один раз (пересборка только при смене вьюпорта/картинки/DPR) и блитит её 1:1
  — без помасштабирования исходника каждый кадр. **Пиксельно идентично** (вид не меняется), экономит самую
  дорогую полноэкранную операцию на high-DPR телефонах.
- **FPS-чек:** `window.__fps` (всегда); экранный счётчик слева-внизу при `?fps=1` (зелёный ≥55 / янтарь
  ≥30 / красный ниже). В превью на самом тяжёлом вьюпорте (ультравайд, DPR 1) — ~100–170 fps, большой
  запас; стоимость тинта/бэкдропа **не зависит от движения тюленя**.
- Если на реальном слабом/high-DPR телефоне просядет: дешёвые рычаги — кэш бэкдропа (уже есть) и убрать
  blur у лучей (`ctx.filter`) на градиентный мягкий край (это бы **чуть** изменило вид лучей). Замер —
  `?fps=1` на устройстве.

### Порядок рисования (`game.js drawFrame`)
Screen-координаты: `drawBackdropFullscreen` (или `drawDeepBackdrop` без бэкдропа) → `drawBorderBack(...,bd)`
→ `drawWaterGradient` (если bd). World-координаты: `drawBackground` (лучи/тинт/пузыри/водоросли). Затем
добыча, тюлень. Сверху: `drawBorderFront` — боковые kelp-walls, поверхность + vignette. Важно:
статичные камни боковой стены остаются в back-layer, а анимированные водоросли — foreground-маркер
границы, который перекрывает тюленя/добычу в боковом бордюре.

> **Заменить арт / бампать кэш:** см. `assets/README.md`; после замены ассетов в `assets/` (или `cover*`)
> — бампать `CACHE` в `sw.js`.

## Финальный экран: переходный «interstitial» (`game.js`)
Конец раунда не режет сразу в результат: сначала **стабильный по времени** дружелюбный экран («Привет,
&lt;имя&gt;! · считаем улов…») c минимальной длительностью `MIN_TRANSITION_MS` (3000 мс). Пока он висит,
в фоне идут сабмит счёта и загрузка доски; результат показывается, когда **готовы и данные, и истёк
минимум** (`Promise.all([load, minTimer])`). Так нет «мигания» загрузки и резкого скачка. Под
`prefers-reduced-motion` мягкая пульсация выключена. Класс `.is-waiting` на `#overlay` прячет
результат/кнопки/доску до готовности.
