# Тюлента / Sealife — Мастер-план (v1)

Соло-разработчик + AI. Human-in-the-loop. Старт: RU/EN. EU compliance — обязателен.

---

## 0. Что изменилось в этой версии

* **Языки:** на старте только RU (база) + EN. Немецкий убран, НО архитектура остаётся мультиязычной — DE добавляется одним конфигом локали позже, без переделки.
* **EU compliance — отдельный обязательный блок** (раздел 10), а не приписка к безопасности.
* **Интегрированы лучшие идеи** из ответов ChatGPT и Gemini: конкретная модель данных, оркестрация агентов (LangGraph/CrewAI + Tavily/Perplexity), OWASP LLM Top-10, комментарии через виджеты TG/VK, privacy-friendly аналитика, glossary/translation memory, print-on-demand.

## 1. Два сайта и синергия

|Домен|Роль|Содержание|
|-|-|-|
|**sealife.info**|Медиа-хаб (лёгкий тон «Тюленты»)|Тюленепедия, факт дня, новости, мемная галерея, игры, квизы, генераторы контента, сообщество|
|**sealrescue.info**|Справочник/спасение (строгий тон)|Каталог реабилитационных центров, «нашёл тюленя — что делать», карта, новости спасения, форма правок, проверенная база знаний|

Постоянная перелинковка в обе стороны:

* sealife → «Нашёл тюленя на берегу? → sealrescue.info»
* sealrescue → «Хочешь узнать больше о тюленях? → sealife.info»

Единая база данных (одна headless CMS), разный UX. Воронка: sealife ловит и удерживает вниманием → sealrescue конвертирует в реальную помощь и донаты.

## 2. Стек (соло + AI)

* **Frontend/backend:** Next.js + **Payload CMS v3** (встраивается в Next, один деплой). Альтернативы: Directus/Strapi. Payload даёт админку-дашборд из коробки, локализацию, контроль доступа, черновики/публикацию.
* **БД:** Postgres (Neon/Supabase).
* **ORM:** Prisma или Drizzle (если что-то вне CMS).
* **Очереди:** BullMQ + Redis (запуск агентов по расписанию и обработка предложений).
* **Поиск по сайту:** Meilisearch/Typesense; позже pgvector/RAG для «спроси про тюленей».
* **Файлы:** S3-совместимое хранилище (Cloudflare R2).
* **Хостинг:** VPS или Vercel/Railway + managed Postgres. **Важно для EU:** для персональных данных предпочесть EU/EEA-регион.
* **CDN/защита:** Cloudflare (free-тариф: DDoS, кэш, Turnstile).
* **Мониторинг:** Sentry + uptime (Uptime Kuma / BetterStack).
* **AI:** через **API** (не через UI-подписки Plus/Pro). Подписки Claude/ChatGPT/Gemini — для ручной разработки; агентам нужен отдельный API-бюджет. Для дешёвых ежедневных задач — Gemini Flash / Claude Haiku.

## 3. Модель данных (ядро)

```
ContentItem
- id, type (article/news/meme/quiz/page)
- status (draft/review/published/archived)
- source_language (ru)
- canonical_slug
- created_at, updated_at, published_at

Translation
- content_id, locale (ru/en[/de])
- title, body
- status (current/stale/review)
- content_hash         # хэш исходника — детектор устаревания перевода

RescueCenter
- name, country, region
- website, email, phone, address, lat/lng
- status (active / unconfirmed / link_broken / needs_check)
- last_checked_at, verification_score
- verified_by_agent_at, verified_by_human_at   # показываем на странице

Source
- url, type (official/news/social/manual)
- trust_level, last_fetched_at

Claim
- entity_type, entity_id
- claim_text, source_id, confidence, status

AgentRun
- agent_name, started_at, finished_at
- status, logs, cost

AgentProposal                # сердце human-in-the-loop
- type, diff, evidence
- confidence
- status (pending/approved/rejected)

UserSubmission
- type, content, status, user_id|null
```

Ключевой принцип: **агент НИКОГДА не пишет в прод напрямую.** Всё идёт через `AgentProposal` → ревью → публикация.

## 4. Пайплайн и 6 агентов

Общий конвейер:

```
Crawler → Extractor → Fact-Checker → Proposal → Human Review → Publish → Translate → SEO Check → Monitor
```

**Агент 1 — Researcher / факт-чекер** (cron, раз в сутки)
Проверяет сайты центров, битые ссылки, изменения контактов/адресов; ищет новые центры и новости. Выдаёт evidence: что изменилось (было/стало), источник (URL), HTML-снапшот, confidence score. **Не решает истину — собирает доказательства.**

**Агент 2 — Content Admin**
Превращает одобренные находки в CMS-черновики, добавляет внутренние ссылки, предлагает заголовки и короткие версии для VK/Telegram. Автопубликация допустима ТОЛЬКО для низкорисковых меток: «ссылка недоступна», «ожидает проверки», «обновлена дата проверки».

**Агент 3 — Translator (integrity)**
RU → EN. Использует translation memory + glossary. Проверяет, что ссылки/имена центров/телефоны/адреса НЕ переведены. Помечает устаревшие переводы (через `content_hash`).

**Агент 4 — SysAdmin**
Uptime, битые ссылки, sitemap/robots/SSL, скорость (Lighthouse/PageSpeed), мониторинг очередей агентов. Алерт в личный Telegram при поломке.

**Агент 5 — SEO**
title/meta/alt, hreflang, canonical, schema.org, sitemap по языкам, внутренняя перелинковка, поиск каннибализации запросов. Всё — как предложения.

**Агент 6 — Security and Compliance**
два раза в месяц проверяет актуальные законы, акты и нормы, требования безопасности и следует ли сайт им, нужно ли выполнять, что можно убрать, что нужно добавить или поменять.

## 5. Оркестрация и инструменты

* **Оркестрация:** LangGraph (граф состояний, точный контроль) или CrewAI (проще ролевые агенты). Для human-in-the-loop LangGraph удобнее — встроены точки прерывания на approval.
* **Поиск/факт-чек:** Tavily или Perplexity API (заточены под агентный веб-поиск).
* **Парсинг:** Playwright в sandbox + extractor (LLM структурирует HTML в поля `RescueCenter`).

---

## 6. Дашборд (операционный центр)

Не «админка ради админки». Экраны:

1. **Очередь изменений** — новые данные, изменения контактов, новые центры, новости-кандидаты, битые ссылки, устаревшие переводы. Кнопки Approve / Reject / Edit, diff «было → стало».
2. **Карточки центров** — редактирование, история, источники, статус проверки.
3. **Контент** — статьи/новости/мемы/квизы/игры, черновики AI.
4. **Переводы** — RU/EN рядом, diff, статус (актуален/устарел/требует проверки).
5. **SEO** — страницы без meta/hreflang/canonical.
6. **Техника** — uptime, ошибки, скорость, broken links, последние agent runs + стоимость.
7. **Модерация** — UGC (подписи к мемам, правки, жалобы).

Любой человек с доступом editor может зайти и обновить контент/перевод вручную в крайнем случае.

## 7. Мультиязычность RU/EN

* Отдельные индексируемые версии `/ru/`, `/en/` (НЕ клиентский автоперевод на лету — это дорого, медленно и плохо для SEO).
* Перевод генерируется заранее как черновик → ревью → публикация (статика).
* **hreflang** для языковых версий (Google это прямо рекомендует), корректные canonical, sitemap по языкам.
* **Translation memory + glossary** (расширять по мере роста):

```
тюлень = seal
морской котик = fur seal
ластоногие = pinnipeds
лежбище = haul-out / rookery (по контексту)
детёныш тюленя = seal pup
нерпа = (Baikal/ringed) seal — уточнять вид
```

* Архитектурно locale — это конфиг. DE добавляется позже без переделки.

## 8. Игры, квизы, вовлечение

Старт с простого (соло-friendly):

* **Квиз** (10 вопросов + результат + share-картинка для VK/TG + рейтинг).
* **«Миф или правда?»** — быстрые карточки с объяснением.
* **«Что делать, если нашёл тюленя?»** — интерактивный rescue-квест (игра + образование одновременно, ведёт на sealrescue).
* **«Угадай вид»** по силуэту/усам.
* **«Тюлень дня»** — daily-механика со streak (факт + мем + вопрос).
* **Генераторы** — «какой ты тюлень сегодня», «тюлений гороскоп», «переведи фразу в тюлений стиль». Дёшево, вирусно, заходит в TG/VK.
* Позже: браузерная аркада на **Phaser.js** (тюлень уворачивается от пластика, ловит рыбу), idle «собери безопасное лежбище».
* Пасхалки → бейджи.

## 9. Социальное (минимальное)

Не строить соцсеть. Опора на существующую аудиторию:

* **Комментарии через виджеты Telegram/VK** — пользователи комментируют со своих аккаунтов. Снимает модерацию спам-ботов И минимизирует персональные данные (важно для GDPR).
* **Реакции без регистрации** (🦭 ❤️ 😂 😭).
* «Предложить мем / факт», «Сообщить об ошибке» (премодерация, без исключений).
* Еженедельный конкурс подписи, лидерборд квизов, бейджи («Юный тюленевед», «Спасатель лежбища»).
* Open Graph share-картинки для VK/TG/X/Reddit.
* Логин через TG/VK — позже, не в MVP.

Самая ценная соц-функция — участие в контенте, не комментарии.

## 10. EU compliance (обязательно)

Применяется, если обрабатываются данные пользователей из EU — независимо от того, где хостинг.

**GDPR / ePrivacy**

* **Минимизация данных** — главный приём: комментарии через TG/VK, реакции без регистрации, без личных кабинетов в MVP → почти нет персональных данных.
* **Cookie-баннер с реальным согласием** (opt-in до загрузки трекеров), отдельные категории.
* **Privacy-friendly аналитика без cookies** — Plausible или Umami (часто не требуют cookie-согласия). НЕ Google Analytics.
* Страницы **Privacy Policy** и **Terms**, контакт для запросов.
* **Право на удаление/доступ** — процедура (хоть и данных минимум).
* **DPA с под-процессорами** (хостинг, CMS, AI-API, аналитика) — у крупных провайдеров есть стандартные.
* **Хостинг персональных данных в EU/EEA**, либо провайдер с валидным механизмом трансфера.
* Формы — защита Cloudflare Turnstile (CAPTCHA-free).

**EU AI Act — transparency**

* Контент, сгенерированный/переведённый AI, **маркировать** («перевод подготовлен AI, проверено: дата» / «черновик AI»).
* Ваш кейс (перевод, фактчек, помощь редактору) — низкий/ограниченный риск; основное обязательство — прозрачность. Конкретные сроки и трактовки уточните перед запуском (правила вводятся поэтапно).

**Accessibility (European Accessibility Act, действует с 2025)**

* Ориентир **WCAG 2.1 AA**: контраст, alt-тексты, навигация с клавиатуры, семантика. Заодно полезно для SEO.

**Дети**

* Контент частично детский → НЕ собирать данные несовершеннолетних, никаких форм с PII в детских разделах.

> Это инженерный чек-лист, а не юридическая консультация. Перед запуском EN/EU-версии стоит сверить детали с актуальными источниками или юристом.

## 11. Безопасность (web + AI)

**AI-agent security (OWASP LLM Top-10)** — релевантно, т.к. агенты читают внешний интернет:

* Угрозы: prompt injection, insecure output handling, sensitive info disclosure, **excessive agency**, supply-chain.
* Меры: агент НЕ имеет unrestricted write в прод; все изменения через `AgentProposal` → approval; **allowlist источников** для критичных данных; **sandbox** для парсинга; **отдельный API-ключ на каждого агента**; **бюджет-лимиты** на AI API; полный **audit log** действий агентов; права агентов — только CREATE/UPDATE, **никогда DELETE**.

**Классический web:**

* HTTPS везде; секреты в `.env`/secret manager, никогда на клиент.
* RBAC: admin / editor / translator / viewer.
* **MFA на админку.**
* Rate-limiting форм и API.
* Ежедневные бэкапы Postgres.
* UGC — премодерация всегда.

## 12. Монетизация и донаты

Аудитория 8к VK + 1.2к TG — не масштаб большой рекламы. Идём через донаты, микро-продукты, спонсорство.

**RU-аудитория:** Boosty, **Telegram Stars** (через бота/mini-app для цифровых товаров), VK Донат (уровни поддержки, ранний доступ), ЮKassa (приём платежей для самозанятых).

**EN/EU-аудитория:** Buy Me a Coffee, Patreon, Ko-fi; крипто-донаты как опция.

**Форматы:**

* Прозрачные **прогресс-бары целей** («на сервер», «на рыбу для центра N» с переводом средств в реальный центр — резко повышает доверие).
* **Мерч через print-on-demand** (Printful/Printify) — без логистики с вашей стороны.
* Платные цифровые наборы: PDF «30 фактов», карточки для детей, материалы для учителей, мини-курс.
* Telegram mini-app «Тюлений квиз», платные стикеры/квесты.
* Спонсорство рубрик («Тюлень недели при поддержке…») — только этичные бренды.
* Партнёрки осторожно: книги, эко-товары, образовательные игрушки, океанариумы/музеи.

> Доступность платёжных рельсов для RU-аудитории меняется часто — проверьте актуальность на момент запуска.

## 13. Перенос на другие ниши

Строим не «сайт про тюленей», а **движок нишевого AI-медиа + справочника**.

```
Niche
- topic, language_base
- entities, sources, content_types
- glossary, games, monetization
```

Тюлени: `entities = species, rescue_centers, news, facts, myths`.
Другие ниши (меняются только схема, источники, glossary, промпты):

* приюты кошек/собак; птицы (виды/заповедники/реабилитация); редкие растения (уход/сохранение); локальный туризм (статус музеев/достопримечательностей).

Агенты (source monitor, fact-checker, content updater, translator, SEO, tech) остаются те же. Отладив пайплайн один раз — клонируете проект за выходные.

## 14. Roadmap (под приоритеты: сайт → агенты → игры → монетизация)

**MVP 1 (4–6 недель) — запустить сайт с контентом**

* sealife.info, структура RU/EN (задел на DE), ~20 evergreen-страниц, 10 квизов/карточек, мемная лента, базовая админка Payload, перевод AI с ручной проверкой, share-картинки TG/VK, cookie-баннер + Plausible/Umami, Cloudflare.

**MVP 2 (4–6 недель) — справочник + первый агент**

* sealrescue.info, каталог 20–50 центров, «последняя проверка», форма правок, Агент-1 (проверка ссылок + изменения), очередь `AgentProposal`.

**MVP 3 — дашборд агентов**

* Агент-2 (контент), Агент-3 (переводы integrity), Агент-5 (SEO), daily digest, авточерновики новостей, донаты, лидерборд квизов.

**MVP 4 — масштаб**

* Telegram bot / mini-app, платные цифровые штуки, полноценная карта центров, Phaser-игры, перенос движка на другие ниши, Агент-4 (tech) на полную.

**Рекомендуемый фокус:** не запускать 5 агентов сразу. Сначала ОДИН сильный конвейер: `ежедневный crawler → найденные изменения → dashboard → approve → publish → translate`. Это уже отличает вас от обычного блога. Остальных агентов добавлять по мере стабилизации.
